Per-library content counts and a server state snapshot, computed on the server. Not part of the Komga API surface, so the endpoints are absent from the OpenAPI spec. They are the kmrs-native way to feed library overviews and admin dashboards: one call returns everything, instead of querying the actuator metrics one meter at a time.

## Library statistics

`GET /api/v1/stats/libraries` — content counts for every library the caller can see, plus their total:

- `libraries` — one entry per visible library, ordered by name: `libraryId`, `name`, `series`, `books`, `fileSize` (bytes), `readlists`, `collections`. Libraries without content report zeros.
- `total` — the same counts over all visible libraries.

All counts cover only the content the user is allowed to see (library sharing and content restrictions apply), matching what a book search would return. For an administrator this is the full library.

Read list and collection counts use the same belongs-to semantics as the list pages: a list counts in every library it has at least one visible member in. A list can therefore appear in several libraries' counts, so `total.readlists`/`total.collections` count each list once instead of summing the per-library rows. Lists with no members belong to no library and are not counted.

## Server statistics

`GET /api/v1/stats/server` — a server state snapshot. Administrator only.

- `tasks` — the background task queue and execution metrics, merged by task type: `queueSize`, and one `types` entry per task type that has queued tasks or recorded executions: `type`, `queued`, `executions`, `totalTimeMs`, `maxTimeMs`, `failures`
- `process` — `startTime`, `uptimeSeconds`, `cpuUsage` (percent of total capacity), `memoryBytes` (resident set size)
- `totals` — global row counts: `libraries`, `collections`, `readlists`, `sidecars`
