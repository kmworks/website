The release Docker image bundles the kmweb React UI (dashboard, browsing with facet filters, full-text search, the comic reader, account settings, live updates over SSE) and serves it at `/` out of the box. Nothing to configure: `http://<host>:25600/` works in a browser immediately.

The bundled UI is built from the same source tree as the server and is version-locked to it: upgrading the image upgrades the UI, and the two never drift out of sync.

## Bare binary

The standalone binary carries no UI, which is fine for API-only clients (KMReader, KOReader, OPDS readers). To serve a UI anyway, build the bundle from the kmrs source tree and point `webui.dir` at it — this is only needed to force a specific UI:

```sh
git clone https://github.com/kmworks/kmrs && cd kmrs/webui
pnpm install && pnpm build   # produces webui/dist
KOMGA_WEBUI_DIR=/path/to/kmrs/webui/dist kmrs
```

Run with an empty `KOMGA_WEBUI_DIR=` to explicitly disable the UI.

## Notes

- KMServer speaks plain HTTP. If you need HTTPS, put any TLS-terminating proxy in front; it can be a dumb pipe, since KMServer tells the SPA and the API apart itself.
- Cross-origin hosting (web UI on a different origin than the API) works once the UI's origin is listed in `cors.allowed-origins` (`KOMGA_CORS_ALLOWEDORIGINS`). Credentialed requests are always allowed, so the wildcard `*` is rejected — list origins explicitly.
- The web UI's files and SPA routes are served without authentication — the login page has to load anonymously. Authentication is enforced by the API, same as the Java version.
